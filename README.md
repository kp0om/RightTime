# RightTime 데이터 수집 앱 (Mac 없이, 무료)

## 1. 현재 단계
개발 1단계: **데이터 수집 앱 v1**. 빌드 점검(알림 응답 기록)에 더해 실제 학습 데이터를 모은다.

## 2. 목적
- 설정한 시간 범위 안의 **무작위 시각**에 시험 reminder를 보내고, 탭·지움·무응답과 응답 시간을 자동으로 기록한다 (Proposal 3.1 자동 라벨링).
- 알림 전달 직전 5분 가속도, 30분 활동 상태, 걸음 수를 Core Motion 기록에서 **나중에 조회**한다. iOS가 기록을 보관하므로 그 순간 앱이 깨어 있지 않아도 된다.
- 앱이 언제 깨어나는지 기록해 iOS 백그라운드 제약을 실측한다 (Feasibility, Proposal 3.3).

## 3. 필요한 파일
| 파일 | 역할 |
|---|---|
| `project.yml` | XcodeGen 설정, 권한 문구, 백그라운드 갱신 설정 |
| `Sources/RightTimeApp.swift` | 앱 시작점, 알림 탭·지움 응답 기록 |
| `Sources/Models.swift` | 알림, 센서 context, 깨어남 기록, 설정 데이터 구조 |
| `Sources/DataStore.swift` | 기기 안 JSON 저장, CSV·JSON 내보내기 |
| `Sources/Scheduler.swift` | 하루 N회 무작위 시각 예약 (3일치 미리), 빠진 예약 복구 |
| `Sources/ContextCollector.swift` | Core Motion 조회 (CMSensorRecorder 가속도, 활동, 걸음 수) |
| `Sources/Pipeline.swift` | 앱이 깨어날 때마다 응답 확정 → context 수집 → 예약 보충 |
| `Sources/ContentView.swift` | 수집 상태, 시간 범위 설정, 권한, 최근 알림, 내보내기, 점검 로그 |
| `Sources/LogStore.swift` | Xcode 콘솔 대신 앱 안에서 보는 점검 로그 |
| `.github/workflows/build-ipa.yml` | GitHub Actions macOS 서버에서 서명 없는 `.ipa` 생성, 컴파일 오류는 annotation으로 표시 |

## 4. 코드
위 파일들이 전부다. 수집 중 기록 항목:
- 알림: 예약 시각, 실제 전달 시각, 결과(탭/지움/무응답), 응답 시각, 응답 시간(초)
- context: 가속도 크기 평균·표준편차·최소·최대, 5 Hz 가속도 크기 시계열(5분, 1D CNN 입력 후보), 활동 구간 목록, 5분·30분 걸음 수
- 앱 깨어남 시각과 이유
- 정확한 위치는 수집하지 않는다.

## 5. 실행 방법

**준비 (한 번만)**
1. 서명 전용 무료 Apple ID를 새로 하나 만든다(본 계정 비밀번호를 서드파티 도구에 넣지 않기 위해).
2. GitHub에서 **공개(Public)** 저장소 `RightTime`을 만든다. 공개여야 macOS 빌드가 무료다.
3. 이 폴더의 파일을 폴더 구조 그대로 저장소 `main` 브랜치에 올린다. (GitHub를 Claude에 연결하면 이 단계는 Claude가 대신 할 수 있다.)
4. Windows PC에 AltServer(AltStore 설치 도구)를 설치한다. 안내: https://faq.altstore.io
5. iPhone: 설정 > 개인정보 보호 및 보안 > 개발자 모드 켜기 (설치 시도 후에 메뉴가 나타날 수 있다).

**빌드와 설치 (코드 바꿀 때마다)**
1. `main`에 올리면 GitHub 저장소의 **Actions** 탭에서 `Build unsigned IPA`가 자동 실행된다(수동 실행도 가능).
2. 성공하면 실행 결과 페이지 아래 Artifacts에서 `RightTime-ipa`를 내려받아 압축을 풀면 `RightTime.ipa`가 나온다.
3. iPhone을 USB로 PC에 연결하고 AltServer(또는 AltStore)로 `RightTime.ipa`를 설치한다. 서명 전용 Apple ID로 로그인한다.
4. iPhone 설정에서 해당 개발자 앱을 신뢰하라는 안내가 나오면 따른다.

## 6. 예상 결과
**설치 점검 (먼저)**
1. `알림 권한 요청`, `모션 권한 요청` → 둘 다 허용.
2. `10초 뒤 시험 알림`을 누르고 홈 화면으로 나가면 10초 뒤 알림이 온다. 탭하면 점검 로그에 `알림 탭: 전달 후 N초`.

**수집 시작**
1. 시간 범위(기본 9시~22시, 하루 7회)를 확인하고 `수집 시작`.
2. `예정된 알림`이 수십 개(오늘 남은 시간 + 이틀치)로 표시된다.
3. 알림이 오면 **알아챘을 때 탭**한다. 원하지 않으면 지워도 된다(지움도 기록된다).
4. 앱을 다시 열면 `최근 알림`에 결과·응답 시간과 `context ✓`가 보인다(전달 5분 뒤부터 조회).
5. `내보내기 파일 만들기` → `CSV·JSON 공유`로 파일 앱이나 PC로 보낼 수 있다.

## 7. 문제 확인 항목
- **GitHub 빌드 실패:** Actions 로그에서 빨간 단계의 마지막 오류 줄을 복사해 Claude에게 보낸다.
- **설치 실패:** AltServer 오류 문구, iPhone iOS 버전, 개발자 모드 상태를 확인한다.
- **앱이 안 열림:** 7일 서명이 만료됐는지 확인한다. AltStore에서 Refresh 하면 데이터는 유지된 채 다시 열린다.
- **알림이 안 옴:** iPhone 설정 > 알림 > RightTime 허용 여부, 집중 모드(방해 금지) 상태를 확인한다.
- **응답 시간이 기록되지 않음:** 점검 로그에 `알림 탭`/`알림 지움`이 찍히는지 본다. 알림센터의 "모두 지우기"는 앱에 전달되지 않아 무응답으로 남는다.
- **context에 가속도 없음:** 점검 로그와 CSV `context_notes` 열을 본다. 가속도 기록은 앱이 깨어날 때마다 12시간씩 켜지므로, 하루 한 번 이상 앱을 열어 두면 끊기지 않는다.
- **백그라운드 갱신:** `앱 깨어남 기록`에 "백그라운드 갱신"이 얼마나 자주 찍히는지가 feasibility 결과가 된다.

## 주의
- 무료 서명 앱은 **7일마다 다시 서명**해야 한다. 데이터 수집 기간에는 갱신 날짜를 정해 두거나 AltStore 백그라운드 갱신을 켜 둔다.
- 기기당 사이드로드 앱은 3개까지다.
- 수집 데이터는 공개 저장소에 올리지 않는다.
